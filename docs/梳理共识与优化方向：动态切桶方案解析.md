# 梳理共识与优化方向：动态切桶方案解析

# 梳理共识与优化方向

1. 否决固定粗细二档桶：预先写死两种尺寸，灵活性不足，无法贴合真实波动强弱梯度

2. 保留逐点遍历动态切桶优势：实时依据数据变化态势切割区间，桶尺寸自然差异化

3. 修正判断逻辑：摒弃单纯相邻单点差值对比，升级为**滑动窗口内统计波动**判定切桶时机，兼顾实时动态切桶形态，又以局部区间波动率作为判定依据，贴合最初标准差评估波动的思路

---

# 方案原理说明

## 双维度定义

- 时间维度：设定单桶最大时长上限，避免区间跨度无限拉长，保障时序展示规整性

- 波动维度：以滑动窗口内数据极差 / 标准差衡量局部波动幅度，幅度超标即刻分割新桶

## 判定逻辑

遍历时序数据时，维护当前累积区间，同时取近期一段窗口数据计算整体波动；
满足任一条件则闭合当前桶，新建桶继续统计：

1. 当前桶累计时长达到最大限制

2. 窗口内数据波动幅度超出设定阈值

区别：不再只比前后单个点差值，而是看一小段数据整体震荡程度，规避单点毛刺误切桶问题；同时桶大小无固定档位，随数据形态自由变化

# 改造后可执行 SQL（MySQL 变量实现动态切桶）

基于你原始查询结构改写，动态生成不等长桶，以局部区间波动作为切分依据

```python
sql_text = f"""
SELECT
    bucket_start AS time_bucket,
    MAX(field_val) AS max_val,
    SUBSTRING_INDEX(GROUP_CONCAT(field_val ORDER BY timestamp ASC), ',', 1) AS avg_val
FROM (
    SELECT
        timestamp,
        {usage_field} AS field_val,
        -- 会话变量维护桶起始时间、窗口缓存数据、上一轮波动值
        @current_bucket := IF(
            -- 条件1：桶时长超限  条件2：局部窗口波动超标
            (timestamp - @bucket_start) > :max_single_bucket_time
            OR ABS(
                (SELECT MAX(v) FROM @data_window) - (SELECT MIN(v) FROM @data_window)
            ) > :fluctuate_threshold,
            timestamp,
            @bucket_start
        ) AS bucket_start,
        -- 更新桶起始标记
        @bucket_start := @current_bucket,
        -- 滑动窗口维护近期数据，用于计算区间波动
        @data_window := JSON_ARRAY_APPEND(@data_window, '$', {usage_field}),
        -- 限制窗口数据条数，只保留近期样本
        @data_window := IF(JSON_LENGTH(@data_window) > :window_size,
                           JSON_REMOVE(@data_window, '$[0]'),
                           @data_window)
    FROM
        {table.__tablename__} FORCE INDEX ({index_name})
    CROSS JOIN (
        SELECT
            @bucket_start := 0,
            @current_bucket := 0,
            @data_window := JSON_ARRAY()
    ) AS init_var
    WHERE
        node = :node
        AND timestamp BETWEEN :start AND :end
    ORDER BY
        timestamp ASC
) AS dynamic_bucket_data
GROUP BY bucket_start
ORDER BY time_bucket;
"""

# 传参调用
db.execute(sql_text, {
    'node': self.node,
    'start': start_time,
    'end': end_time,
    'max_single_bucket_time': 15000,  # 单个桶最大时长 15000毫秒
    'fluctuate_threshold': 18,        # 区间波动阈值
    'window_size': 8                  # 滑动窗口保留数据点数
}).fetchall()
```

# 关键特性对比

|方案|桶尺寸|波动判定依据|灵活性|失真风险|
|---|---|---|---|---|
|全局统一步长均分桶|全部等长|全局整体波动率|低|高，尖峰易形态畸变|
|固定粗细二档桶|仅两种固定尺寸|单桶内部极差|中|中等，无法适配梯度波动|
|相邻单点差值切桶|自由不等长|前后单个数据差值|高|偏高，单点异常易误切割|
|滑动窗口波动切桶（当前方案）|自由不等长|小段区间整体波动|极高|低，兼顾动态形态与真实波动|

# 适配原有业务逻辑说明

1. 结果字段保留你原有`time\_bucket`、`max\_val`、首值均值，上层渲染逻辑无需改动

2. 索引依旧沿用原有覆盖索引，查询性能损耗可控

3. 参数可灵活调优：窗口点数、最大桶时长、波动阈值，适配不同监控指标特性

4. 动态生成的桶没有预设大小档位，平稳时段自动拉长区间，剧烈波动自动细密切分

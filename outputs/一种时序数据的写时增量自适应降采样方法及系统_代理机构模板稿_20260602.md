## 一、本发明的名称

一种时序数据的写时增量自适应降采样方法及系统。

本发明属于时序数据存储、查询优化与可视化处理领域，具体涉及一种在通用数据存储系统上对大规模监控类时序数据执行写时增量自适应降采样的方法，以及实现该方法的系统。

## 二、背景技术的方案

### 2.1 技术背景

在高性能计算集群、云平台监控系统、数据中心资源监控系统等场景中，CPU 使用率、内存使用量、网络流量等指标通常以 5 秒至 60 秒的周期持续采集，并以时序数据的形式写入数据库。前端监控面板需要按照用户指定的时间范围实时展示趋势曲线。随着保留时长增加，原始时序数据量迅速膨胀，若直接对原始数据进行前端绘图，会带来查询慢、前端渲染负担重、交互不流畅等问题，因此工程上普遍需要先进行降采样。

围绕时序数据降采样，目前公开方案大致可归纳为 5 个方向：查询侧降采样算法、写时预聚合方案、预测模型降采样、分布式大数据处理方案，以及自适应阈值或动态采样方案。经检索与对比，本案正文中保留并重点分析了 8 篇与本发明最相关的现有技术。

### 2.2 与本发明最接近的现有技术

#### 2.2.1 查询侧降采样方案

该类方案在用户发起查询后，再从原始数据表中读取指定时间范围内的全量原始时序数据，然后在应用层执行降采样计算，典型代表为 `LTTB` 及其变体。

1. `CN117891972A`：采用滑动窗口动态降采样策略，在每个滑动窗口内选取目标抽样量的数据点，本质上属于查询阶段执行的特征点选择方案。
2. `CN202011579516`：提出 LTTB 与 TimeGap 混合的特征点选择方案，也是在查询阶段对全量原始数据执行再计算。

该类方案的共同特点是：

- 必须在查询时重新扫描指定时间范围内的原始数据；
- 查询范围越大，扫描和计算成本越高；
- 一般仅输出有限特征点，难以同时兼顾趋势形态和查询性能。

#### 2.2.2 写时预聚合方案

该类方案在数据写入后预先生成聚合结果，查询时直接读取聚合结果，以减少查询时的计算量。

1. `CN122112135A`：通过 `CDC + Kafka + NiFi + TimeScaleDB` 的链路，将增量数据同步进入时序数据库，并利用其连续聚合功能生成物化视图。
2. `CN117891588A`：利用 OpenCL 将降采样预计算卸载至 GPU/FPGA 执行，桶窗口为固定的预设时间间隔。

该类方案的共同特点是：

- 查询路径较轻，但桶划分通常采用固定时间窗口；
- 聚合窗口由配置静态决定，难以根据数据波动自动调整；
- 工程实现常绑定特定数据库产品、消息链路或专用硬件。

#### 2.2.3 预测模型降采样方案

1. `CN117520423A`：通过历史数据训练多项式预测模型，再对目标采样时间点直接输出预测值。

该类方案的特点是：

- 输出结果为模型近似值而非精确统计值；
- 需要训练过程，新增数据难以实时反映；
- 对突发尖峰、阶跃等结构变化的保真能力有限。

#### 2.2.4 分布式大数据处理方案

1. `CN202011467348`：通过 `PySpark + Pandas` 混合架构处理大规模时序数据。

该类方案的特点是：

- 依赖 Spark 等分布式计算框架；
- 适合大规模离线处理，不适合低成本、轻量级在线部署；
- 架构复杂，运维和集成门槛较高。

#### 2.2.5 自适应阈值或动态采样方案

1. `CN101051952A`：通过固定阈值 `K/D` 的趋势检测机制调节网络流量抽样比。
2. `CN121327179A`：通过时间间隔阈值决定是否停止本轮采样，并在降采样/全量采样之间切换。

该类方案虽然涉及“自适应”或“动态采样”概念，但其共同特点是：

- 阈值或判定条件仍为人工预设固定值；
- 适配的是采样比率或策略切换，而不是可视化降采样中的桶边界划分；
- 未形成“阈值由数据自身波动特征自动演进”的闭环机制。

### 2.3 现有技术方案的总体概括

综合上述 8 篇现有技术可以看出，目前最接近本发明的技术路线主要有三类：

1. 查询侧降采样：查询时读取原始数据并现算降采样结果；
2. 写时预聚合：写入后按照固定窗口提前聚合；
3. 固定阈值动态采样：依赖人工设定阈值，在采样率或采样策略层面调整。

这些方案分别在查询性能、工程部署、趋势保真等方面取得了一定效果，但尚未形成一种在通用数据存储系统上即可实现的、面向监控曲线展示的、写入时增量执行且阈值可随数据波动自动演进的降采样方案。

## 三、背景技术的缺陷

结合上述现有技术，至少存在以下 5 项缺点：

### 3.1 查询侧方案重复扫描原始数据，查询开销随查询范围扩大而显著增加

查询侧降采样方案本质上都要求在用户查询时重新读取指定时间范围内的全量原始数据，再执行排序、选点和返回。对于监控系统这种高频缩放、频繁回看的场景，查询范围越大，扫描与计算成本越高，查询延迟越不稳定。

### 3.2 桶划分方式僵化，关键参数依赖人工配置，难以跨指标复用

现有写时预聚合方案大多采用固定时间窗口，固定阈值方案则依赖人工预设阈值。对于 CPU、内存、网络流量等量纲和波动模式差异明显的指标，往往需要分别调参，同一指标在不同时段也容易出现原参数失效的问题。

### 3.3 对数据形态变化和查询范围变化的适应性不足

现有方案通常只能在某一类典型波动模式或某一固定查询范围下表现较好。当查询范围从 1 天扩展到 7 天甚至更长时，查询侧方案常需要重新设定输出点数或桶数；当数据从平稳段进入剧烈波动段时，固定窗口或固定阈值方案又难以及时调整桶密度。

### 3.4 基于 raw min/max 的波动度量容易受瞬时毛刺干扰

若直接采用桶内最大值和最小值计算波动幅度，则单个异常点即可显著放大桶内波动估计，造成桶边界误判，并进一步干扰后续阈值更新，使系统在含尖峰、毛刺的监控场景下稳定性较差。

### 3.5 部分现有方案基础设施依赖重、技术栈绑定深

部分方案依赖 GPU/FPGA 等专用硬件，部分方案绑定特定时序数据库、消息中间件或 Spark 集群，不利于在通用数据库和常规应用服务栈中低成本落地部署。

---

## 四、本发明的目的

针对上述缺点，本发明要解决的技术问题是：

在不依赖 GPU/FPGA 专用硬件、不引入分布式计算集群、不绑定特定数据库产品的前提下，如何在通用数据存储系统上实现大规模时序数据的实时降采样，使降采样结果在数据写入时即自动生成且实时可见，桶划分判定阈值随数据特征自动调节而无需人工配置，且桶内关键特征值提取能够有效抵抗瞬时毛刺干扰。

围绕该总体目标，具体包括以下 5 个目的：

1. 将降采样操作从查询侧前移到写入侧，避免每次查询重复扫描全量原始数据；
2. 在每条原始数据入库时实时判定桶边界，使桶划分不再依赖固定窗口；
3. 使波动阈值能够随数据自身波动特征自动演进，减少跨指标、跨阶段调参；
4. 在写时增量处理过程中提取既能表达主要趋势、又能抗毛刺干扰的桶内特征；
5. 使整个方案能够建立在通用数据存储系统和常规软件栈之上，便于工程部署。

---

## 五、本发明的方案

### 5.1 技术方案总体思路

本发明的核心思路是：将降采样操作从查询时前移至写入时。每当一条原始时序数据写入存储系统时，即触发一次增量桶划分判定。系统维护一个轻量级状态机和当前开口桶的内存缓冲区，在写入路径上以“时间上限 + 波动阈值”双维度条件共同决定是否闭合当前桶；桶闭合后，输出该桶的 8 字段桶摘要结果，并利用该桶的实际波动幅度通过 EWMA 更新下一桶的波动阈值。查询时直接读取已生成的降采样结果，而不再扫描原始数据。

### 5.2 系统组成

本发明的系统至少包括以下模块：

1. **数据采集代理**：负责采集 CPU 使用率、内存使用量等监控指标，并将 `series_id`、时间戳 `ts`、数值 `value` 写入原始数据存储；
2. **时序原始数据存储**：按 `series_id + ts` 存储原始监控数据；
3. **桶状态维护模块**：维护当前开口桶的状态变量，并在每次写入时执行双维度切桶判定；
4. **阈值自适应模块**：在桶闭合时根据桶内实际波动幅度用 EWMA 更新波动阈值 `F`；
5. **降采样结果存储**：存储已闭合桶对应的 8 字段桶摘要结果，并额外记录 `series_id`；
6. **查询服务与前端渲染模块**：查询时按 `series_id + bucket_start` 范围直接读取降采样结果，并按时间顺序渲染趋势曲线。

### 5.3 原始数据与降采样结果的数据结构

原始数据存储示例如下：

```sql
CREATE TABLE metrics_raw (
  series_id VARCHAR(64) NOT NULL,
  ts INT NOT NULL,
  value DOUBLE NOT NULL,
  INDEX idx_series_ts (series_id, ts)
);
```

降采样结果存储示例如下：

```sql
CREATE TABLE metrics_summary (
  series_id VARCHAR(64) NOT NULL,
  bucket_start INT NOT NULL,
  bucket_end INT NOT NULL,
  first_val DOUBLE NOT NULL,
  P5_val DOUBLE NOT NULL,
  P5_ts INT NOT NULL,
  P95_val DOUBLE NOT NULL,
  P95_ts INT NOT NULL,
  last_val DOUBLE NOT NULL,
  PRIMARY KEY (series_id, bucket_start)
);
```

其中，`series_id` 用于标识所属监控序列，例如 `cpu_usage`、`memory_usage` 等。需要说明的是，本发明中“8 字段桶摘要结果”指的是 `bucket_start`、`bucket_end`、`first_val`、`P5_val`、`P5_ts`、`P95_val`、`P95_ts`、`last_val` 这 8 个桶摘要字段；`series_id` 是附加的序列标识字段，用于支持多序列并行管理和查询。

### 5.4 写入时增量双维度自适应桶划分

桶状态维护模块记录如下状态变量：

| 状态变量 | 含义 |
|------|------|
| `T0` | 当前开口桶的起始时间戳 |
| `first_val` | 当前桶内第一条数据的值 |
| `buffer[]` | 当前桶内数据点缓冲区，每项为 `(value, timestamp)` |
| `count` | 当前桶内累计数据条数 |

对每条新数据 `(Ti, Vi)`，执行以下逻辑：

```text
IF no_open_bucket THEN
    T0 = Ti
    first_val = Vi
    buffer = [(Vi, Ti)]
    count = 1
    等待下一条数据
ELSE
    buffer.append((Vi, Ti))
    count += 1

    sort(buffer by value)
    P5_val  = buffer[floor(count × 0.05)].value
    P5_ts   = buffer[floor(count × 0.05)].timestamp
    P95_val = buffer[floor(count × 0.95)].value
    P95_ts  = buffer[floor(count × 0.95)].timestamp
    bucket_range = P95_val - P5_val

    条件1：Ti - T0 > Tmax
    条件2：(Ti - T0 > Tmin) AND (bucket_range > F)

    IF 条件1 OR 条件2 THEN
        输出 8 字段桶摘要结果
        EWMA 更新 F
        以当前点开启下一开口桶，并将当前点同步写入新桶 buffer
    ELSE
        等待下一条数据
    END IF
END IF
```

其中：

- `Tmax` 为时间上限参数，用作安全阀，防止桶无限拉长；
- `Tmin` 为最小累计时长参数，防止桶刚开启时因局部扰动被误切；
- `F` 为波动阈值，由 EWMA 自动维护。

### 5.5 波动阈值的 EWMA 自适应调节

本发明不再采用人工固定阈值，而是在每个桶闭合时，根据该桶的实际波动幅度 `bucket_range = P95_val - P5_val` 更新波动阈值：

```text
F_new = α × bucket_range + (1 - α) × F_old
F = max(F_new, F_min)
```

其中：

- `α` 为平滑系数，取值范围为 `0 < α < 1`；
- `F_min` 为阈值下限，防止阈值衰减至噪声级别；
- `F_initial` 为初始阈值，可由保守经验值给出，再由 EWMA 自动收敛。

该机制的效果是：

- 当数据持续剧烈波动时，`bucket_range` 较大，`F` 被拉高；
- 当数据持续平稳时，`bucket_range` 较小，`F` 被逐步拉低；
- 当数据从平稳转为剧烈波动，或从剧烈波动转为平稳时，EWMA 的滞后效应会在过渡期自动调整桶宽。

### 5.6 采用 P5/P95 分位数代替 raw min/max

为提高对瞬时毛刺的鲁棒性，本发明不以桶内最大值和最小值计算波动范围，而以 `P95_val - P5_val` 作为桶内波动度量。单个异常尖峰只会影响排序后极少数位置，不会像 raw min/max 那样直接放大整桶极差，因此更适合用于驱动桶划分和阈值更新。

### 5.7 查询与渲染方式

查询阶段直接按 `series_id + bucket_start` 范围读取 `metrics_summary` 中的降采样结果，而不访问对应时间范围内的全量原始数据。前端在渲染时，对每个桶中的 4 个值点按照时间戳排序后依次连线，用于恢复桶内的主要走势。

## 六、本发明的关键点

本发明的关键点主要包括：

1. 每条原始时序数据写入时即触发桶划分判定，降采样发生在写入路径而不是查询路径；
2. 通过时间上限 `Tmax` 与波动阈值 `F` 双维度条件共同决定桶边界，而不是仅依赖固定时间窗口或单一阈值；
3. 在内存缓冲区中保存当前开口桶的数据点，并在缓冲区中提取 `P5/P95` 分位值及其时间戳；
4. 采用 `P95 - P5` 分位数极差代替 raw min/max，提升对瞬时毛刺的抗干扰能力；
5. 桶闭合后输出 8 字段桶摘要结果，并额外记录 `series_id` 作为序列标识字段；
6. 波动阈值通过 EWMA 自动更新，并设置阈值下限 `F_min`，实现跨指标、跨阶段自适应；
7. 查询阶段直接按 `series_id + 时间范围` 读取 8 字段桶摘要结果，无需重新扫描该范围内的全量原始数据。

## 七、本发明的效果

与现有技术相比，本发明至少具有以下技术效果：

### 7.1 查询路径轻量，查询范围扩大后仍保持低耗时

本发明将主要计算过程前移到写入阶段，查询时只需读取已生成的降采样结果。实施例中，在 7 天全程查询下，CPU 场景查询耗时约 `1.423 ms`，内存场景约 `1.522 ms`；而查询侧 `LTTB` 分别约为 `52.105 ms` 和 `56.278 ms`，固定窗口聚合分别约为 `7.179 ms` 和 `9.516 ms`。

### 7.2 阈值能够自动适配不同量纲和不同波动模式的监控指标

在完全相同的 `Tmax/Tmin/alpha/F_initial/F_min` 参数下，CPU 场景最终阈值收敛到约 `46.80`，内存场景最终阈值收敛到约 `6.70`，说明阈值可根据数据自身波动尺度自动演进，无需为不同指标分别预设不同阈值。

### 7.3 趋势保真能力较好

在 1 天公平预算对比中：

- CPU 场景下，本发明 `NRMSE=0.2887`，优于查询侧 `LTTB` 的 `0.5476` 和固定窗口聚合的 `0.4082`；
- 内存场景下，本发明 `NRMSE=0.5785`，优于查询侧 `LTTB` 的 `1.4624` 和固定窗口聚合的 `1.4853`。

### 7.4 查询范围扩大时无需重新调参，稳定性更好

当查询范围从 1 天扩大到 7 天时，本发明无需重新设定查询侧参数，输出点数会随查询范围自然扩展；而外部方法若沿用 1 天查询确定的参数，其误差会明显上升。实施例中：

- CPU 场景下，查询侧 `LTTB` 的 `NRMSE` 上升至 `0.7429`，固定窗口聚合为 `0.6441`，本发明仍为 `0.2865`；
- 内存场景下，查询侧 `LTTB` 的 `NRMSE` 为 `0.2037`，固定窗口聚合为 `0.2069`，本发明仍为 `0.0298`。

### 7.5 部署要求低，工程落地性好

本发明仅依赖通用数据存储系统的基础能力和应用层状态机逻辑，不依赖专用硬件、分布式集群或特定数据库中间件，适用于通用监控系统的在线部署。

## 八、本发明的实例

### 8.1 实施例名称

实施例一：统一参数下 CPU 与内存监控指标的综合验证实验。

### 8.2 应用场景

某高性能计算集群监控系统持续采集各节点 CPU 使用率与内存使用量数据，并在 Web 监控面板中展示指定时间范围的趋势曲线。为验证本发明方法在不同数据形态上的统一参数适配能力、趋势保真能力以及减少查询侧调参的能力，选取 CPU 使用率与内存使用量两个典型场景开展综合实验。

### 8.3 数据规模与场景特征

| 场景 | 原始数据点数 | 数据形态 | 说明 |
|------|------------:|----------|------|
| CPU 使用率 | 120,960 | 周期波动 + 噪声 + 尖峰 | 用于验证连续周期型时序的趋势保持能力 |
| 内存使用量 | 120,960 | 平台段 + 阶跃变化 + 局部回落 | 用于验证结构型台阶信号的保真能力 |

### 8.4 统一参数设置

| 参数 | 数值 |
|------|----:|
| `Tmax` | 1800 秒 |
| `Tmin` | 60 秒 |
| `α` | 0.4 |
| `F_initial` | 50.0 |
| `F_min` | 5.0 |

### 8.5 实施流程

1. 采集代理每 5 秒采集一次 CPU 使用率和内存使用量数据，并以 `series_id`、`ts`、`value` 的形式写入 `metrics_raw`；
2. 每条数据写入时触发桶状态维护模块，若无开口桶则创建新桶并将首点同步写入 `buffer`；
3. 若已有开口桶，则将 `(value, timestamp)` 加入缓冲区，排序后提取 `P5_val`、`P5_ts`、`P95_val`、`P95_ts`，并计算 `bucket_range = P95_val - P5_val`；
4. 满足 `Ti - T0 > Tmax` 或 `((Ti - T0 > Tmin) AND (bucket_range > F))` 时闭合当前桶；
5. 桶闭合后，将 `series_id` 连同 8 字段桶摘要结果一起写入 `metrics_summary`，并按 `F_new = max(alpha * bucket_range + (1-alpha) * F_old, F_min)` 更新波动阈值；
6. 查询时直接按 `series_id + bucket_start` 范围读取 `metrics_summary`，前端按时间顺序连接桶内 4 个值点。

### 8.9 实施例总结

综上，本实施例验证了：

1. 本发明方法在统一参数下能够跨不同数据形态的监控指标自动适配；
2. 在公平预算条件下，本发明比查询侧 `LTTB` 和固定窗口聚合具有更好的趋势保真能力；
3. 在查询范围扩大时，本发明无需重新设置查询侧参数，仍能保持稳定结果；
4. 本发明在减少查询侧调参、保持趋势保真和实现写时增量处理方面具有明显技术优势。
